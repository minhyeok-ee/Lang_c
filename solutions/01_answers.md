### Q1. 포인터 연산과 증감 연산자
- `*p++`: 후위 `++`가 `*`보다 우선순위가 높지만, 후위라서 **현재 값(10)을 쓰고** p를 arr[1]로 이동
- `*++p`: p를 먼저 arr[2]로 이동한 뒤 역참조 → 30
- `++*p`: p가 가리키는 **값**을 증가 → arr[2] = 31
- `*(p + 1)`: arr[3] → 40

> 핵심: `*p++`는 포인터 이동, `(*p)++`와 `++*p`는 값 증가.

### Q2. static 지역 변수
`static int n`은 처음 한 번만 초기화되고 함수가 끝나도 값이 유지된다(data/bss 영역).
`int m`은 호출될 때마다 스택에 새로 만들어져 항상 1이 된다.
→ 11, 21, 31

### Q3. 구조체 패딩
CPU는 int를 4의 배수 주소에 두는 것을 선호하므로(정렬), 컴파일러가 빈 바이트(패딩)를 넣는다.
구조체 전체 크기도 가장 큰 멤버 정렬 크기의 배수가 된다.

```
struct A: c(1) + pad(3) + i(4) + d(1) + pad(3) = 12
struct B: i(4) + c(1) + d(1) + pad(2)          = 8
struct C: c(1) + pad(1) + s(2) + d(1) + pad(1) = 6
```
> 실무 포인트: 멤버를 큰 타입부터 배치하면 메모리를 아낄 수 있다.
> 통신 패킷이나 레지스터 맵처럼 패딩이 없어야 할 때는 `#pragma pack(1)`이나
> `__attribute__((packed))`를 쓰지만, 정렬되지 않은 접근은 일부 CPU(ARM 등)에서 느리거나 예외가 날 수 있다.

### Q4. 매크로의 함정
- `SQUARE(a + 1)` → `a + 1 * a + 1` → `3 + 3 + 1` = **7** (16이 아님)
  → 올바른 매크로: `#define SQUARE(x) ((x) * (x))`
- `MAX(i++, j)` → `((i++) > (j) ? (i++) : (j))`
  비교할 때 i++ (5 > 3, i=6), 참이므로 다시 i++ (값 6, i=7) → m = **6**, i = **7**
  → 매크로 인자는 여러 번 평가될 수 있으므로 부작용 있는 인자를 넣으면 안 된다. `static inline` 함수가 대안이다.

### Q5. 부호 없는 정수 비교와 정수 승격
- `s < u`: int와 unsigned int를 비교하면 **int가 unsigned로 변환**된다.
  -1 → 0xFFFFFFFF(4294967295)이므로 `4294967295 < 1`은 거짓 → **B**
- `unsigned char c = 255; c++` → 8비트를 넘어 **0**으로 돌아감 (unsigned 오버플로는 정의된 동작)
- `x << 1`: unsigned char는 연산 전에 **int로 승격**되므로 0x80 << 1 = 0x100 = **256**
  (unsigned char 변수에 다시 저장하면 0이 된다)

### Q6. 배열과 포인터의 sizeof
- `sizeof(arr)`: int 10개 → 40
- 함수 매개변수 `int a[]`는 사실 `int *a`다(배열이 포인터로 decay) → 4
  → 그래서 배열을 함수에 넘길 때는 길이를 따로 넘겨야 한다.
- `sizeof(s)`: 포인터 → 4
- `sizeof(t)`: "hello" + '\0' = 6
- `strlen(t)`: '\0' 제외 = 5

### Q7. 연산자 우선순위
- `x & 0x10 == 0`: `==`가 `&`보다 우선순위가 높다 → `x & (0x10 == 0)` → `x & 0` → 0 → **N**
  → 의도대로 하려면 `(x & 0x10) == 0` (이렇게 하면 Y)
- `1 << 2 + 1`: `+`가 `<<`보다 우선순위가 높다 → `1 << 3` = **8**

> 비트 연산자(`& | ^`)는 비교 연산자(`== !=`)보다 우선순위가 낮다. 비트 연산은 항상 괄호로 감싸자.

### Q8. 2차원 배열
- `*(m + 1)`은 m[1] (행), `*(m + 1) + 2`는 &m[1][2] → **7**
- `m[2] + 3`은 &m[2][3] → **12**
- `sizeof(m) / sizeof(m[0])` = 48 / 16 = **3** (행 개수)

### Q9. 값 전달, 포인터 전달, 함수 포인터
- C는 항상 **값에 의한 전달(call by value)**이다. `swap_value`는 복사본만 바꾼다 → `1 2`
- 주소를 넘기면 원본을 바꿀 수 있다 → `2 1`
- `ops[1]`은 mul, `ops[0]`은 add → 12 + 3 = **15**
  → 함수 포인터 배열은 펌웨어에서 명령 테이블, 상태 머신, 인터럽트 벡터 테이블에 쓰인다.

### Q10. switch fall-through
case 2로 들어가서 `break`를 만날 때까지 아래 case를 계속 실행한다 → **23**

### Q11. 단락 평가
- `a++ && b++`: a++의 값은 0(거짓)이므로 **오른쪽은 실행하지 않는다**. a=1, b=0
- `a++ || b++`: a++의 값은 1(참)이므로 **오른쪽은 실행하지 않는다**. a=2, b=0

### Q12. union과 엔디안
union 멤버는 같은 메모리를 공유한다.
리틀 엔디안은 **낮은 자리 바이트를 낮은 주소**에 저장한다.

```
주소:  c[0] c[1] c[2] c[3]
값:     78   56   34   12
```
→ **78 12** (빅 엔디안이면 12 78)

> 엔디안 확인 코드: `int x = 1; if (*(char *)&x == 1) /* 리틀 엔디안 */`

### Q13. sizeof 안의 식
`sizeof`는 (가변 길이 배열이 아니면) **컴파일 시간에 타입만 보고 계산**하므로 `n++`는 실행되지 않는다.
→ n = **5**, s = **4**

### Q14. 문자열 배열과 인덱싱
- `char s[] = "abc"`는 수정 가능한 배열이므로 `p[1] = 'X'`가 가능 → "aXc"
  (`char *s = "abc"`였다면 문자열 리터럴 수정이라 정의되지 않은 동작 → 크래시 가능)
- `*(s + 2)` = s[2] = 'c'
- `2[s]`는 `*(2 + s)`와 같으므로 s[2] = 'c' (덧셈은 교환 법칙 성립)

### Q15. 정수 나눗셈
C99부터 정수 나눗셈은 **0 방향으로 버림**이다.
- 7 / 2 = 3
- -7 / 2 = -3.5 → **-3** (-4가 아님)
- 나머지는 `(a / b) * b + a % b == a`를 만족해야 하므로 -7 % 2 = -7 - (-3 × 2) = **-1**
  → 나머지의 부호는 피제수(왼쪽)를 따른다.
